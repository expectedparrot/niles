Expected Parrot · Local-first relationship operations

A CRM even Lionel Hutz can operate

Niles gives an agent a safe command layer for clients, conversations, promises, intake forms, and follow-up—without turning a relationship history into an opaque SaaS database.

Package: nilesInterface: JSON CLIStorage: local-firstExample firm: Hutz Law

01 What Niles does

Lionel Hutz has prospects, clients, phone calls, promises, referrals, and a recurring problem: none of them stay connected. Niles turns those fragments into an auditable relationship workflow that both Lionel and his agent can operate.

Remember the relationship

Contacts, organizations, notes, traits, tags, and source history remain connected and searchable.

Remember the promise

Every next step becomes an assignable, dated task rather than a sentence buried in a call note.

Invite new information

EDSL surveys support internal debriefs, human intake, and targeted client-status requests.

Keep humans in control

Imported responses and model recommendations enter review queues. Nothing changes client records until accepted.

The operating idea. An agent uses commands, not storage files. Every command returns one structured JSON envelope with data, warnings, errors, and safe next steps.

02 The base data model

Niles is deliberately small. A contact is the center of the graph; notes explain what happened, tasks state what must happen, and surveys turn repeatable questions into deterministic updates.

ObjectWhat it means at Hutz LawImportant behavior
ContactBurns Industries or Waylon SmithersName, company, role, email, cadence, traits, and tags
NoteA liability call or engagement discussionTimestamped interaction history with a source kind
TaskSend the engagement outline by FridayOpen, done, blocked, or cancelled; optionally assigned and dated
SurveyA client debrief or intake questionnaireQuestions plus deterministic routes into notes, traits, and tasks
FormA locally registered EP human surveyConnects remote metadata to a local intake or status workflow
SubmissionA prospective client’s answersQuarantined until accepted, merged, or rejected
RecommendationA proposed next relationship actionQuarantined until accepted as a task or rejected

Every mutation appends an event. The local index can be rebuilt from that history, so history, undo, fsck, and cloning all share one source of truth.

03 Install and initialize Hutz Law

python -m pip install "niles[edsl] @ git+https://github.com/expectedparrot/niles.git"

mkdir hutz-law
cd hutz-law
git init
niles init
niles agent next

niles agent next is the orientation endpoint for an agent. It reports counts, the command contract, safe handoff sequences, and the next useful action.

What the envelope guarantees
{
  "schema_version": "niles.envelope.v1",
  "status": "ok",
  "command": "agent next",
  "data": {
    "initialized": true,
    "state_contract": {"storage": "managed_by_niles"}
  },
  "warnings": [],
  "errors": [],
  "next_steps": []
}
No storage ceremony. Niles manages its event log, index, survey definitions, and EP exchange artifacts. Users and agents work through commands; they do not inspect or stage internal files.

04 Add clients and the people around them

Start with Burns Industries as the account and Smithers as the person Lionel actually speaks with.

niles contact add "Burns Industries" \
  --tag prospect \
  --trait source=ambulance-adjacent-referral \
  --trait priority=1 \
  --cadence-days 14

niles contact add "Waylon Smithers" \
  --company "Burns Industries" \
  --role "Executive Assistant" \
  --email smithers@burns.example \
  --tag decision-maker

niles contact list --tag prospect
niles contact show burns-industries

References can be exact IDs, emails, or unambiguous slugs. Reuse the identifiers returned in envelopes for mutations.

niles contact update burns-industries --trait priority=2
niles contact tag burns-industries --add active-opportunity --remove prospect
niles contact merge burns-industries duplicate-burns \
  --note "Consolidate duplicate account"

05 Log an interaction, then debrief it

niles note add burns-industries \
  "Discussed workplace liability. Smithers requested an engagement outline." \
  --kind call

niles note list burns-industries
niles contact show burns-industries --with-notes

Free-form notes record what happened. Surveys handle repeatable structure.

niles survey copy debrief client-debrief
niles survey show client-debrief
niles survey run client-debrief --contact burns-industries

niles survey run client-debrief \
  --contact burns-industries \
  --answers debrief-answers.json \
  --dry-run

niles survey run client-debrief \
  --contact burns-industries \
  --answers debrief-answers.json
Preview first. Deterministic routes can append notes, set traits, add tags, and create tasks. --dry-run shows those mutations without writing events.

06 Turn promises into work

niles task add burns-industries \
  "Send engagement outline" \
  --due 2026-09-10 \
  --assign lionel \
  --tag proposal

niles task list --assignee lionel
niles task update <task-id> --due 2026-09-11
niles task done <task-id> --note "Sent to Smithers"
niles task suggest --assignee lionel

task suggest is local prioritization, not a model call. Give the agent enough firm context to make the surrounding record useful:

niles org context set \
  "A scrappy Springfield law practice seeking legitimate recurring clients." \
  --name "Hutz Law" \
  --trait principal=lionel

niles teammate add "Lionel Hutz" --alias lionel --role attorney
niles material add "Engagement letter" \
  --path templates/engagement.pdf --tag sales

07 Surface neglect before clients disappear

niles status
niles contact list --stale
niles survey run review --contact burns-industries
niles report status --html hutz-status.html

Cadence makes neglect measurable. List stale contacts, then run the built-in review survey for each relationship that needs attention. The HTML report provides a shareable local snapshot.

Pipeline

Tags and traits distinguish prospects, clients, referrals, and active opportunities.

Activity

Notes and events show which relationships are moving.

Neglect

Cadence compares the last interaction with expected follow-up.

Promises

Task views expose overdue, assigned, and blocked work.

08 Find new clients with human intake

Lionel wants a public intake form. Niles prepares and records the workflow, but it never contacts Expected Parrot.

Niles · local

  • Export the Survey
  • Manage exchange paths
  • Register metadata
  • Import into quarantine
  • Apply review decisions
⇄

EP · network

  • Publish the human survey
  • Host respondent access
  • Retrieve responses
  • Own authentication
niles intake export intake-basic
# Run data.publish_command from the returned envelope.

niles intake register intake-basic
# Run data.pull_command from the returned envelope.

niles intake import <local-form-id>
niles intake status
niles intake review

The final decision is explicit:

niles intake review <submission-id> --accept
niles intake review <submission-id> --merge burns-industries
niles intake review <submission-id> --reject \
  --note "Prank call from Bart"

niles intake close <form-id>
Untrusted until reviewed. Import never creates or edits a client. Acceptance creates a contact and applies safe routes; merge attaches information to an existing relationship; rejection preserves the audit record without mutation.

09 Ask a known client what changed

A status request uses the same boundary but targets a known relationship and recipient.

niles status-request export client-debrief
# Run data.publish_command.

niles status-request register client-debrief \
  --contact burns-industries \
  --recipient smithers@burns.example
# Run data.pull_command.

niles status-request import <local-form-id>
niles status-request status
niles status-request review
niles status-request review <submission-id> --accept

Accepted answers follow deterministic routes into the existing contact. Rejected answers remain in history and make no relationship change.

10 Ask a model for the next relationship action

Niles can package selected CRM context as an EDSL job. The model runs outside Niles, and every proposed action returns to quarantine.

niles recommend export next-steps --tag prospect
# Run data.run_command with ep.

niles recommend import --name next-steps
niles recommend review
niles recommend accept <recommendation-id> \
  --assign lionel \
  --due 2026-09-15
niles recommend reject <recommendation-id>
Project CRM context
Export EDSL job
Run with ep
Import to quarantine
Accept as task
The review gate is structural. Importing a recommendation cannot create a task. Only recommend accept can do that.

11 Search, inspect, and undo

niles search "workplace liability"
niles search "engagement letter"
niles history --contact burns-industries --limit 20
niles undo <event-id>
niles fsck
niles rebuild-index

Search spans names, notes, traits, tags, and tasks. Undo appends a compensating event and refuses unsafe reversals with dependents.

niles import csv prospects.csv
niles import csv prospects.csv --commit
niles export csv --tag prospect
niles export json

CSV import is a preview by default. Mapping mistakes should be visible before they become relationship history.

12 Sync and restore without storage bookkeeping

niles sync --dry-run
niles sync --message "Update Hutz Law CRM"

niles sync --no-push --message "Before the Burns meeting"

Niles knows which state is durable. It commits only that state, excludes its rebuildable index and managed exchange artifacts, preserves unrelated staged work, and pushes unless --no-push is set.

niles export hutz-law.zip

mkdir hutz-law-restored
cd hutz-law-restored
niles import /path/to/hutz-law.zip
niles fsck

Archives contain durable CRM history and rebuild their local index after import. Existing state is protected unless --replace is explicit.
